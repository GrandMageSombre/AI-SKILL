# AI-SKILL

自用 AI Skill 合集：经过实战打磨的智能体工作流与编码规范，可直接放进支持 Agent Skill 的 IDE/CLI（如 Trae、Claude Code）中使用。

    └── SKILL.md                   # Conventional Commits 提交规范

## Skill 一览

| Skill | 用途 | 典型触发场景 |
|-------|------|--------------|

## 1. code-review：多智能体四视角代码审查

单人视角会漏问题。本 skill 让四个"专家人格"**并行**审查同一段改动，再由主智能体**回读源码逐一核实**，输出可追溯的审查报告。

### 四个视角

| 视角 | 审查什么 |
|------|----------|
| **架构与分层** | 分层是否清晰、依赖方向、抽象边界、可扩展性、命名 |
| **正确性与边界** | 算法/协议/业务逻辑、空值、越界、异常路径、边界条件 |
| **线程与资源** | 并发安全、竞态、锁/定时器、文件句柄、内存、退出清理 |
| **交互与体验** | UI 布局、状态反馈、错误提示、误操作防护、无障碍 |

视角可按项目类型替换：非 UI 项目把第 4 个换成**测试与可测性**；协议项目重点看帧解析边界、字节序、CRC；嵌入式项目重点看栈/堆、看门狗、IO 时序。

### 核心纪律

- **并行发起**：在同一条消息里发出 4 个子智能体调用，并发执行
- **prompt 自带上下文**：子智能体看不到对话历史，需明确列出要读的文件、具体核对点、输出格式与字数上限
- **主智能体必须核实**：子智能体的结论不一定准确，每条严重结论都要回读源码确认，误报要在报告中标注澄清
- **问题分级**：P0 严重（立刻修）/ P1（本轮必修）/ P2 建议 / P3 可选
- **配套产出**：每轮生成 `审查报告N.md` 并同步更新 `版本说明.md`（feat → minor+1，fix → patch+1，破坏性变更 → major+1）

### 完整流程

```
实现功能 → 跑测试 → 四视角并行审查 → 回读源码核实 → 当场修复并复测
→ 写审查报告 → 更新版本说明 → 询问用户修复范围 → 按 conventional-commit 规范提交
```

## 2. conventional-commit：Conventional Commits 提交规范

规范的提交信息是项目的第一手文档：三个月后回看 `git log`，一眼就知道"这次为什么改、改了什么"。

### 格式

```
<类型>(<范围>): <描述>

<正文：为什么改 / 改了什么 / 怎么验证>

<脚注：BREAKING CHANGE / Closes / Co-authored-by>
```

### 常用类型与版本号联动

| 类型 | 用于 | 版本号影响 |
|------|------|------------|
| `feat` | 新功能 | **minor +1**（1.2.0 → 1.3.0） |
| `fix` | 修 bug | **patch +1**（1.3.0 → 1.3.1） |
| `docs` / `refactor` / `perf` / `test` / `build` / `ci` / `chore` | 文档 / 重构 / 性能 / 测试 / 构建 / 流水线 / 杂项 | 不变 |

**破坏性变更**：类型后加 `!` + 脚注 `BREAKING CHANGE:` → **major +1**（1.x → 2.0.0）。

### 示例

```bash
fix(protocol): LEN 超限判错并重同步, 防止吞帧

伪造的大 LEN 会让解析缓冲长时间等一个永远到不了的帧,
期间到达的正常帧被连带丢弃。

- 新增 MAX_PAYLOAD=64 上限, 超限按错误帧处理并计数
- 补测试: 伪造 LEN=255 后紧跟正常帧, 验证正常帧仍被解析

测试: python tests/test_protocol.py (12 项全过)
```

### 关键要点

- 描述**中文、动词开头、≤ 50 字**、结尾不加句号，拒绝 `update` / `fix bug` 这类无信息描述
- 范围用目录名或模块名（如 `ui`、`protocol`），一眼定位改动位置
- 复杂改动必写正文三段式：**为什么改 / 改了什么 / 怎么验证**
- 一次提交只干一件事，不把重构和功能混在一起

## 安装与使用

1. 将 skill 文件夹（含 `SKILL.md`）复制到你的 AI 工具的 skills 目录，例如：
   - Trae：项目 `.trae/skills/` 或全局 skills 目录
   - Claude Code：`~/.claude/skills/`
2. 无需额外配置，skill 会在匹配场景（代码审查、编写提交信息）自动触发，也可在对话中点名调用。
